# Fotbool — Unity mobile football foundation

هذا المشروع **أساس برمجي تجريبي، وليس لعبة جاهزة للنشر**. يحتوي السكربتات الأربعة المطلوبة وتبعياتها ومولّد مباراة 11 ضد 11 باستخدام مجسمات بسيطة. لا يتضمن أصولاً فوتوريالية أو بيانات أندية مرخّصة أو مشاهد جاهزة محفوظة.

## التقنية

- Unity **2022.3.62f1 LTS**، C#، URP **14.0.11**.
- Android / iOS، لعب محلي دون خادم أو multiplayer.
- المحاور: Y للأعلى، Z بطول الملعب، X بالعرض. متر واحد = وحدة Unity؛ ملعب 105 × 68م، كرة نصف قطرها 0.11م.
- لا يُستخدم Unreal بالتوازي: C# وURP موجهان إلى Unity، ونقل المشروع إلى Unreal يتطلب إعادة تنفيذ بـC++/Blueprints.

## تشغيل المشروع خطوة بخطوة في VS Code وUnity

1. ثبّت Unity Hub والمحرر **2022.3.62f1** مع Android Build Support وSDK/NDK/OpenJDK. ثبّت iOS Build Support عند تجهيز مسار iOS.
2. من Hub اختر **Add project from disk** وحدد `D:\Fotbool`. افتح بالمحرر المحدد واترك Package Manager ينتهي. افحص Console؛ استعادة الحزم تحتاج اتصال إنترنت.
3. افتح `D:\Fotbool` في VS Code وثبّت الإضافات المقترحة. في Unity: **Edit → Preferences → External Tools → External Script Editor → Visual Studio Code** ثم **Regenerate project files**. تكامل VS Code الحديث يعتمد حزمة Visual Studio Editor الموجودة في manifest، وليس حزمة VS Code القديمة.
4. من **Assets → Create → Rendering → URP Asset (with Universal Renderer)** أنشئ أصل URP داخل `D:\Fotbool\Assets\_Project\Settings`. عيّنه في **Project Settings → Graphics** وفي مستويات **Quality** المستخدمة. الحزمة وحدها لا تفعّل URP.
5. في **Player → Other Settings → Active Input Handling** اختر **Input Manager (Old)** أو **Both**؛ التحكم الحالي يستخدم `UnityEngine.Input`، وليس Input System الجديد. في **Time** ابدأ بـFixed Timestep = **0.02**.
6. أنشئ مشهداً فارغاً واحفظه باسم `D:\Fotbool\Assets\_Project\Scenes\Match.unity` (أنشئ المجلد أولاً). أضف GameObject باسم Bootstrap واربط به `MatchBootstrapper` فقط. اختَر Difficulty في Inspector. لا تضف اللاعبين أو MatchManager يدوياً في هذا المشهد.
7. اضغط **Play**. المولّد ينشئ الملعب والكرة و22 لاعباً وAI والإضاءة والكاميرا والتحكم والإعادة. المشهد مناسب لفحص الميكانيك فقط.
8. اختيارياً أضف `AdaptiveGraphics` إلى Bootstrap بعد إعداد URP. `ObjectPool` مكوّن مستقل: عيّن prefab وcapacity في Inspector، واستدعِ `Rent` ثم `Return` من نظام التأثيرات؛ لا يُستخدم تلقائياً في مشهد التجربة.
9. أضف مشهد المباراة إلى **Build Settings → Scenes In Build**. لا تعدّل ملفات `.csproj` التي يولدها Unity يدوياً، ولا تعتمد `dotnet build` وحده للتحقق من مشروع Unity.

### التحكم

- سطح المكتب: WASD للحركة نسبة إلى الكاميرا؛ Shift للركض؛ J تمرير؛ K بينية؛ L تسديد؛ Space تدخل؛ U مهارة؛ Tab اختيار أقرب لاعب منزلي للكرة؛ C تغيير الكاميرا.
- الهاتف: اسحب النصف الأيسر؛ زيادة طول السحب تشغّل الركض. الأزرار اليمنى للإجراءات. لا يزال هذا IMGUI تجريبياً بإحداثيات بكسل، وليس UI إنتاجياً يدعم safe area وجميع المقاسات.
- زر Replay يعرض آخر نحو عشر ثوانٍ المسجّلة؛ يلزم تسجيل عينتين على الأقل. يتوقف وقت المباراة أثناء الإعادة ويعود إلى الحالة السابقة عند الخروج.
- إدارة النادي واجهة برمجية مستقلة؛ أضف `ClubManager` إلى كائن إدارة ثم استدعِ `CreateClub` قبل البيع/الشراء والتدريب. لم تُنفّذ شاشة إدارة أو ربط career بمشهد المباراة.

## الاختبارات والتحقق

افتح **Window → General → Test Runner → EditMode → Run All**. الاختبارات في `D:\Fotbool\Assets\_Project\Tests\EditMode\CoreTests.cs` تغطي الأوزان، المدخلات المعيبة، درجات AI، حفظ مجموع الأموال وملكية اللاعب، رفض العروض، وحدود التدريب والتشكيلات.

لتشغيل الاختبارات آلياً أغلق المشروع في المحرر أولاً، ثم من PowerShell نفّذ الأمر التالي إذا كان Unity مثبتاً في هذا المسار:

```powershell
& 'C:\Program Files\Unity\Hub\Editor\2022.3.62f1\Editor\Unity.exe' -batchmode -nographics -projectPath 'D:\Fotbool' -runTests -testPlatform EditMode -testResults 'D:\Fotbool\TestResults.xml' -logFile 'D:\Fotbool\UnityTests.log'
```

لا تضف `-quit` لتشغيل Test Runner؛ دعه يغلق بعد الاختبارات. افحص XML وسجل المحرر، لا تعتمد على غياب رسائل الطرفية. قد يلزم تفعيل ترخيص المحرر مسبقاً.

**حالة التحقق في بيئة الإنشاء:** لم يُعثر على Unity في المسارات المفحوصة، لذا لم تُنفّذ عملية import/compile أو الاختبارات أو بناء Android/iOS. تمت مراجعة السكربتات ساكناً فقط؛ نجاح التشغيل غير مُثبت. لا توجد بدائل UnityEngine أو نتائج اختبار مصطنعة في المشروع.

## البناء للأجهزة

- Android: ARM64 + IL2CPP، اختبر Vulkan وOpenGLES3 على مصفوفة أجهزة، واستخدم AAB وتوقيع إصدار خاصاً للإرسال إلى المتجر. تحقق من متطلبات Target API الحالية؛ لا تُثبتها على قيمة قديمة.
- iOS: IL2CPP + ARM64 + Metal. بناء الأرشيف والتوقيع النهائي يتطلب **macOS وXcode** وحساب Apple وإعداد provisioning؛ Windows وVS Code لا يكفيان.
- أبقِ build development منفصلاً عن release. قِس الحرارة والذاكرة ووقت CPU/GPU على الأجهزة الفعلية لا في Game View فقط.

## ما تم تنفيذه (الحالة الحالية)

### 기본ية المباراة (Core Gameplay)
- مباراة 11 ضد 11 مع مولّد تلقائي للملعب واللاعبين والكاميرا (MatchBootstrapper)
- فيزيائية كرة واقعية: جر هواء، تأثير ماغنوس (الدوران)، ارتداد، احتكاك circulating، تحديد اللمسة الأخيرة
- حركة اللاعبين: sprint، لياقة تنخفض عند الركض وتستعيد عند الراحة، دوران سلس نحو اتجاه الحركة
- التمرير العادي والبينية، التسديد بقوة ومنحنى، التدخل، المهارة الفردية
- اكتشاف الأهداف (عبور خط المرمى بالكامل)، شوطان، Kickoff بعد الهدف وعند بداية الشوط الثاني

### الذكاء الاصطناعي (AI)
- FootballAI: شجرة أولوية + FSM، خمسة مستويات صعوبة (VeryEasy..VeryHard)، قرارات التمرير/التسديد/المراوغة/التدخل
- TacticalAI: تشكيلات 4-3-3 و 4-4-2، عقلية دفاعية/متوازنة/هجومية، ضغط تكتيكي متكيف حسب النتيجة والوقت
- GoalKeeperAI: حارس مرمى متطور - انزلاق على خط المرمى، خروج لاعتراض الكرة، إمساك، تشتيت، توزيع الكرة لبدء البناء من الخلف

### قوانين المباراة (FootballRules)
- التسلل (Offside) مع فحص المدافع الثاني الأخير
- ركلات الركنية (Corner) عند خروج الكرة من خط المرمى بلمسة مدافع
- ركلات المرمى (Goal Kick) عند خروج الكرة بلمسة مهاجم
- رميات التماس (Throw In) عند خروج الكرة من خط التماس
- الأخطاء (Fouls) والبطاقات الصفراء والحمراء مع احتمال طرد اللاعب عند البطاقة الثانية
- التبديلات (Substitutions)

### واجهة المستخدم (UI)
- UIManager لإدارة شاشات: القائمة الرئيسية، واجهة المباراة (HUD)، الإيقاف، نتيجة المباراة، المسار الوظيفي
- عرض النقاط والوقت والتحكم في الحيازة والاستحواذ
- أزرار الإيقاف والاستئناف والعودة للقائمة الرئيسية

### الصوت (Audio)
- SoundManager中央ي مع مصادر للموسيقى والمؤثرات والبيئة
- أصوات: صافرة البداية/النهاية، هدف، خطأ، بطاقة، ركلة كرة، تدخل، هتاف جمهور، تغيير لاعب

### الإدارة والمسار الوظيفي (Management & Career)
- ClubManager: إنشاءクラブ، شراء/بيع لاعبين بشروط مالية، توظيف مدرب، تدريب سمات، أسبوعيات
- CareerManager: حفظ وتحميل المسار الوظيفي عبر JSON، تسجيل نتائج المباريات، الميزانية، النقاط المكتسبة
- TournamentManager: جدول مباريات دور Double Round-Robin، ترتيب الفرق، النقاط، فارق الأهداف

### الأداء (Performance)
- AdaptiveGraphics: تعديل دقةrendering تلقائياً حسب معدل الإطارات (FPS)
- ObjectPool: مجمع كائنات للتأثيرات والأ Props

### العروض البصرية (Presentation)
- CameraController: ثلاث زوايا (Broadcast، Action، DynamicFollow) مع انتقالات ملساء
- ReplayRecorder: تسجيل وإعادة آخر 10 ثوانٍ من المباراة مع شبح (ghost) للممثلين

### التحكم (Inputs)
- سطح المكتب: WASD للحركة، Shift للركض، J تمرير، K بينية، L تسديد، مسافة تدخل، U مهارة، Tab تبديل لاعب، C تغيير كاميرا، Esc إيقاف
- اللمس: مقود افتراضي على اليسار، أزرار إجراءات على اليمين (تجريبي IMGUI)

### الاختبارات (Tests)
- CoreTests: اختبارات وحدة للتقييم العام، المدخلات الخاطئة، صعوبة AI، konservação المال في الانتقالات، رفض العروض غير الصالحة، حدود التدريب، صحة تشكيلات الملعب
